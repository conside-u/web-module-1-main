## Рішення щодо рефакторингу

### Модулі
- **`routes.js`**: Відповідає за HTTP-логіку, прийом запитів, маршрутизацію, перевірку статус-кодів і формування відповідей клієнту.
- **`services.js`**: Містить бізнес-логіку валідацію вхідних даних за правилами API та розрахунок загальної вартості замовлення `total`.
- **`store.js`**: Управляє станом даних у пам'яті зберігання, пошук за `id`, створення та видалення замовлень.

### Очищення коду
- Винесено змішування HTTP-логіки та роботи з пам'яттю з єдиного монолітного файлу `app.js` у модульну архітектуру.
- Всі функції та логіку збережено для підтримки працездатності поточних тестів, але рознесено по відповідних файлах.

### API-контракт
- Зовнішня поведінка перевірена за допомогою запуску наявного набору автоматизованих тестів (`npm test`). Усі тести проходять успішно (pass 4), маршрути, методи та коди стану (201, 204, 400, 404) залишено без змін.

### Швидкодія

До:    середня затримка 1161 ms / p50 1311 ms / p95 1942 ms / p99 1991 ms / пропускна здатність 20.9 req/s
Після: середня затримка 1164 ms / p50 1313 ms / p95 1931 ms / p99 1982 ms / пропускна здатність 21.0 req/s

- **Найповільніші ендпоінти**: `GET /orders/:id` (1458 ms) та `POST /orders` (1449 ms).
- **Причина**: Штучні затримки (`setTimeout` на 900–2000 мс у функції `synchronizeOrderState`), які закладені в початковому коді завдання для емуляції довгої обробки даних.

### Перевірка AI-змін
- **Зміна**: Пропозиція використання бібліотеки `joi` для валідації вхідних об'єктів.
- **Перевірка та рішення**: Перевірив код валідації вручну. Відмовився від пропозиції AI, оскільки поточні правила валідації легко реалізуються на базовому JS без додаткових зовнішніх залежностей, що відповідає вимозі не ускладнювати архітектуру.
